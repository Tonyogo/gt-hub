# Mobile Terminal Cursor-Line Keyboard Trigger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restrict mobile virtual keyboard wake-up on terminal canvas tap to only the active cursor input line (with a ±1 row touch tolerance), preventing accidental keyboard popups when scrolling or viewing terminal output on mobile devices.

**Architecture:** We add a pure helper function `isTouchOnCursorLine` in `frontend/src/utils/mobileViewportHelper.ts` that compares the touched terminal buffer row (`viewportY + viewportRow`) against the active cursor buffer row (`baseY + cursorY`) within a configurable tolerance (default `1`). In `WebTerminalView.tsx`, mobile single-tap (`handleTouchEnd`) checks `isTouchOnCursorLine`: if matched, it focuses the terminal and helper `textarea`; if not matched, it prevents default synthetic mouse/click events (`e.preventDefault()`) so neither xterm nor the outer wrapper focuses the hidden `textarea`. Desktop click-to-focus and the `TerminalAccessoryBar` keyboard toggle button remain unchanged.

**Tech Stack:** TypeScript, React 18, `@xterm/xterm`, Jest.

**Spec:** Approved in-chat bounded design (2026-10-26).

## Global Constraints

- Default row tolerance for mobile cursor-line tap detection: `tolerance = 1` (`Math.abs(touchBufferRow - cursorBufferRow) <= tolerance`).
- Desktop (`!isMobileRef.current`) click-to-focus behavior must remain unchanged (clicking anywhere on the terminal focuses `xterm`).
- Mobile `TerminalAccessoryBar` keyboard toggle button (`handleToggleKeyboard`) must still open/close the virtual keyboard unconditionally regardless of scroll position.
- Existing test expectations in `tests/terminalMobileSmoothPush.test.ts`, `tests/terminalMobileResizeStability.test.ts`, and `tests/terminalMobileKeyboard.test.ts` must continue to pass.
- Always run targeted Jest test files (`npm test -- tests/<file>.test.ts`) during development.

## Review Focus

- Tapping on historical scrollback lines when scrolled up (`viewportY < baseY`): `touchBufferRow` is near `viewportY`, while `cursorBufferRow` (`baseY + cursorY`) is at the bottom of the buffer — must return `false` and not wake the keyboard.
- Synthetic `mousedown` / `click` events generated by mobile browsers ~300ms after `touchend`: when tapping outside the cursor line on mobile, `touchend` must call `if (e.cancelable) e.preventDefault()` AND the outer canvas wrapper `onClick` must guard `!isMobileRef.current` so synthetic click events cannot focus xterm's `textarea`.
- Invalid / NaN / negative row numbers or negative tolerance values passed to `isTouchOnCursorLine`: must safely return `false` (or clamp tolerance to `>= 0`).
- Tapping within ±1 row of the cursor when the terminal is shifted upward (`cursorShiftY > 0` while keyboard is open or opening): `getCellCoordsFromTouch` uses `screenEl.getBoundingClientRect()`, which automatically reflects CSS `transform: translateY(-cursorShiftY)`, so `viewportRow` remains accurate.
- Multi-line command wrap or alternate buffer (e.g. `vim`, `htop`, `less`): `baseY` is `0` in alternate buffer and `cursorY` is the active cursor row; `isTouchOnCursorLine` works identically using `baseY + cursorY`.

      if (!isDragging && elapsed < 350) {
        const cell = getCellCoordsFromTouch(touchStartX, touchStartY);
        const cursorBufferRow = (term.buffer.active.baseY || 0) + (term.buffer.active.cursorY || 0);
        if (cell && isTouchOnCursorLine({ touchBufferRow: cell.bufferRow, cursorBufferRow })) {
          // Single tap on cursor input line -> Focus terminal & wake on-screen virtual keyboard synchronously
          if (isMobileRef.current && standaloneRef.current) {

          term.focus();
          const textarea = container?.querySelector('textarea');
          if (textarea) {

        } else {

          if (e.cancelable) {
            e.preventDefault();
          }
        }
      }
