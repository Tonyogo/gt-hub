# 移动端定时任务与任务管理显示优化设计规范 (Design Spec)

- **日期**: 2026-10-19
- **状态**: Approved
- **作者**: Claude Assistant & gt-hub Team
- **范围**: 前端 `TerminalCronView`、`TerminalTaskView`、`CronJobModal`、`CronLogModal`、`CreateTaskModal`、`TaskLogModal`

---

## 1. 背景与目标

### 1.1 现状与痛点
在目前的 `gt-hub` Web 控制台中，定时任务（Cron）和后台任务（Tasks）视图主要使用桌面端宽表格（`<table>`）展示。在移动端（手机窄屏 < 640px）访问时存在以下体验问题：
1. **表格过度依赖横向滚动**：包含任务 ID、名称、Cron 表达式/命令、状态、耗时、启动时间、操作等多列，在移动端需左右拖拽，操作按钮极易被挤出屏幕外。
2. **统计指标与工具栏在窄屏下拥挤折行**：任务管理的 4 个统计指标在小屏占据大量垂直首屏高度；顶部搜索框、刷新按钮与操作按钮在窄屏下容易换行错位。
3. **弹窗（Modal）尺寸与形式在小屏体验差**：采用居中悬浮框，键盘弹起容易遮挡表单，长日志内容在手机端上下留白浪费且滑动不便。

### 1.2 优化目标
1. **触控与视觉优��**：手机端（`< 640px`）自动切换为原生 App 般紧凑直观的卡片流列表（Card List），桌面端（`>= 640px`）无缝保留原有完整表格。
2. **空间利用率最大化**：任务管理将 2x2 统计卡片与状态筛选胶囊无缝融合，节约至少 120px 垂直屏幕高度。
3. **底部抽屉（Bottom Sheet）体验**：表单和日志弹窗在小屏自适应切换为贴底抽屉，配合顶部手柄条与平滑滑动动画，适配 iOS 底部安全区。

---

## 2. 详细技术方案

### 2.1 响应式断点策略
- 使用 Tailwind `sm:` 断点（`640px`）：
  - `< 640px` (移动端)：渲染卡片列表、紧凑工具栏、底部抽屉弹窗。
  - `>= 640px` (桌面/平板端)：渲染现有表格及居中弹窗，功能与样式完全向后兼容。

---

### 2.2 列表卡片流架构

#### 2.2.1 定时任务卡片 (`TerminalCronView`)
在 `< 640px` 下，渲染单个卡片容器：
- **卡片头部**：
  - 状态指示圆点（运行中呼吸、已暂停灰色、正常绿色） + 任务名称（高亮加粗）。
  - 右侧状态标签：运行中 / 已暂停 / 成功 / 失败 / 跳过。
- **卡片内容区**：
  - 执行来源：显示 `hub:脚本名` 或终端图标加命令，超长文本优雅截断。
  - 调度信息：Cron 表达式徽标���如 `*/5 * * * *`） + 下次触发倒计时（如 `3 分钟后`） + 上次执行耗时。
- **卡片底部操作条**：
  - 水平排列操作按钮，高度维持 `min-h-[36px]` 便于触摸：
    - `立即运行` (Play 图标)
    - `暂停 / 恢复` (Pause / Play 图标)
    - `查看日志` (FileText 图标)
    - `编辑` (Edit2 图标)
    - `删除` (带内联确认防误触)

#### 2.2.2 后台任务卡片 (`TerminalTaskView`)
在 `< 640px` 下：
- **卡片头部**：
  - 任务短 ID（带一键复制按钮）。
  - 状态标签（运行中动画、已完成绿色、失败红色、已终止灰色） + 退出码徽章（如 `0`、`1`）。
- **执行命令区**：
  - 黑色背景等宽字体命令块，单行/双行截断，点击卡片直接打开该任务日志。
- **时间与耗时**：
  - 耗时（如 `1.5s`） + 启动时间。
- **操作条**：
  - 突出显示“查看日志”按钮。
  - 运行中任务独有：红色“终止”按钮（带二次确认）。

---

### 2.3 顶部工具栏与统计指标优化

#### 2.3.1 工具栏自适应
- 搜索框在移动端设置默认宽度 `w-28`，聚焦时自动展开为 `w-36` 或弹性填充，确保与刷新按钮、新建按钮单行并列不溢出。
- 按钮间距精简为 `space-x-1.5`，标题保持紧凑排版。

#### 2.3.2 统计���标与筛选融合 (`TerminalTaskView`)
- 在移动端（`< sm`），隐藏原有的 2x2 统计卡片网格，将统计数字直接并入状态筛选 Pill（例如：“全部 12”、“运行中 1”、“已完成 10”、“失败 1”）。
- 在桌面端（`>= sm`）依然展示统计大卡片，双端无缝衔接。

---

### 2.4 弹窗与日志抽屉（Bottom Sheet / Drawer）

涉及组件：
1. `CronJobModal` (创建/编辑定时任务)
2. `CronLogModal` (定时任务日志)
3. `CreateTaskModal` (新建任务)
4. `TaskLogModal` (后台任务日志)

**样式与交互统一**：
- 桌面端：`items-center justify-center p-4`，居中卡片 `rounded-2xl`。
- 移动端：
  - 容器位置：`items-end justify-center p-0 sm:p-4`，贴合屏幕底部。
  - 容器外观：`w-full max-h-[88vh] rounded-t-2xl rounded-b-none border-t border-white/10`。
  - 顶部手柄指示条：`w-10 h-1 bg-white/20 rounded-full mx-auto my-2.5`。
  - 动画过渡：`animate-in slide-in-from-bottom duration-200`。
  - 底部安全区：添加 `pb-[max(1rem,env(safe-area-inset-bottom))]` 适配全面屏手势条。
  - 滚动支持：内部表单与日志内容区域 `overflow-y-auto`，长日志或输入法弹起时可自如滑动。

---

## 3. 边界情况与防错处理

1. **超长命令截断**：使用 `truncate` 和 `break-all`，辅以浮动提示或点击进入详情查看全量文本。
2. **内存与渲染保护**：日志弹窗继续遵守 500KB 截断保护，防止大日志造成移动端浏览器闪退。
3. **触控防误触**：
   - 定时任务删除操作保留内联确认态。
   - 后台任务终止保留确认交互。
   - 所有按钮均有符合 WCAG 标准的点击触控区域（>= 36px）。

---

## 4. 验证计划

1. **前端编译与类型检查**：运行 `npm run build:frontend`，确保 TypeScript 与 Tailwind 编译无错误。
2. **自动化测试**：执行 `npm test`，确保现有的所有单元测试与集成测试通过。
3. **多设备视口响应式测试**：
   - 375px（iPhone SE 等小屏）
   - 390px - 430px（iPhone 14/15/16 等主流手机）
   - 768px 及以上（iPad/桌面端）
